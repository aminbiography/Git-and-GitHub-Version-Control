## Overview

Git is a distributed version control system that tracks changes in source code and other files. GitHub is a cloud-based platform that hosts Git repositories and supports collaboration, code review, and project management.

This repository brings together commonly used Git commands, practical repository workflows, and Markdown formatting examples for creating organized GitHub documentation.

## Project Objectives

- Explore practical Git and GitHub version-control workflows.
- Organize commonly used Git commands into functional categories.
- Demonstrate repository creation, configuration, synchronization, and maintenance.
- Understand branch management, commit history, and change recovery.
- Demonstrate GitHub README Markdown syntax and nested document structures.
- Support coding exploration, technical research, and practical experimentation with version control.

## Git and GitHub Fundamentals

| Term | Description |
|---|---|
| Git | A distributed version control system. |
| GitHub | A platform for hosting and collaborating on Git repositories. |
| Repository | A project directory tracked by Git. |
| Commit | A recorded snapshot of repository changes. |
| Branch | An independent line of development. |
| Merge | The process of combining changes from different branches. |
| Remote | A reference to a repository hosted elsewhere. |
| Clone | A local copy of an existing repository. |
| Push | Sends local commits to a remote repository. |
| Pull | Fetches and integrates changes from a remote repository. |
| Fetch | Downloads remote updates without integrating them into the current branch. |
| Pull Request | A GitHub collaboration feature for proposing and reviewing changes. |

## Getting Started

### Install Git

Download Git for your operating system:

[Git Official Website](https://git-scm.com/)

Verify the installation:

```bash
git --version
```

### Configure Your Git Identity

Set your name and email address:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

Review your configuration:

```bash
git config --list
```

### Navigate to Your Project Directory

```bash
cd /path/to/your/project
```

Replace `/path/to/your/project` with your actual project directory.

## Repository Setup and Configuration

### Initialize a New Repository

Create a new Git repository in the current directory:

```bash
git init
```

### Clone an Existing Repository

Download an existing remote repository:

```bash
git clone https://github.com/username/repository-name.git
```

### Check Repository Status

```bash
git status
```

### Configure the Default Branch Name

```bash
git branch -M main
```

### Configure a Remote Repository

```bash
git remote add origin https://github.com/username/repository-name.git
```

Display configured remote repositories:

```bash
git remote -v
```

Change the remote repository URL:

```bash
git remote set-url origin https://github.com/username/new-repository.git
```

## Essential Git Workflow

The standard Git workflow consists of modifying files, staging changes, committing them, and synchronizing commits with a remote repository.

### 1. Check Changes

```bash
git status
```

### 2. Stage Files

Stage a specific file:

```bash
git add filename
```

Stage all changes in the current directory:

```bash
git add .
```

### 3. Commit Changes

```bash
git commit -m "Describe your changes"
```

### 4. Push Changes to GitHub

```bash
git push origin main
```

### 5. Pull Updates from GitHub

```bash
git pull origin main
```

### 6. Fetch Remote Updates

```bash
git fetch origin
```

### Typical Workflow

```bash
git status
git add .
git commit -m "Update project files"
git push origin main
```

## Branch Management

Branches allow developers to work on different features or changes without directly modifying the main development branch.

### List Branches

```bash
git branch
```

List local and remote branches:

```bash
git branch -a
```

### Create a Branch

```bash
git branch feature-name
```

### Switch Branches

```bash
git switch feature-name
```

Alternatively:

```bash
git checkout feature-name
```

### Create and Switch to a New Branch

```bash
git switch -c feature-name
```

### Merge a Branch

First switch to the destination branch:

```bash
git switch main
```

Then merge the feature branch:

```bash
git merge feature-name
```

### Delete a Local Branch

```bash
git branch -d feature-name
```

Force-delete a local branch:

```bash
git branch -D feature-name
```

### Delete a Remote Branch

```bash
git push origin --delete feature-name
```

### Merge Without Fast-Forward

```bash
git merge --no-ff feature-name
```

### Abort a Merge

```bash
git merge --abort
```

## Remote Repository Management

Remote commands help synchronize local repositories with GitHub and other Git hosting platforms.

| Command | Description |
|---|---|
| `git remote -v` | Displays configured remote repositories. |
| `git remote add origin <url>` | Adds a remote repository. |
| `git remote set-url origin <url>` | Changes the remote URL. |
| `git fetch origin` | Downloads updates from the remote repository. |
| `git fetch --all` | Fetches updates from all configured remotes. |
| `git pull origin main` | Fetches and integrates remote changes. |
| `git push origin main` | Pushes local commits to the remote branch. |
| `git ls-remote <url>` | Lists references available in a remote repository. |
| `git remote prune origin` | Removes stale remote-tracking references. |

### Push a New Local Branch

```bash
git push -u origin feature-name
```

The `-u` option establishes the upstream tracking relationship. Afterward, you can generally use:

```bash
git push
git pull
```

### Force Push

```bash
git push --force origin main
```

Use force pushing cautiously because it can overwrite remote branch history.

A safer alternative in many collaborative workflows is:

```bash
git push --force-with-lease origin main
```

## Commit and History Management

Git records project changes through commits. These commands help inspect and manage repository history.

### View Commit History

```bash
git log
```

Display a compact history:

```bash
git log --oneline
```

Display history as a graph:

```bash
git log --graph --oneline
```

Display commits by a particular author:

```bash
git log --author="Author Name"
```

Display a summary grouped by author:

```bash
git shortlog
```

### Inspect a Specific Commit

```bash
git show <commit_hash>
```

### Modify the Most Recent Commit

```bash
git commit --amend
```

Commit staged changes without editing the existing commit message:

```bash
git commit --amend --no-edit
```

### Display Reference History

```bash
git reflog
```

### Retrieve a Full Commit Hash

```bash
git rev-parse <commit_reference>
```

### Identify Changes to Individual Lines

```bash
git blame filename
```

## Comparing Changes

Use Git comparison commands to inspect differences between files, commits, and staging areas.

| Command | Description |
|---|---|
| `git diff` | Shows unstaged changes. |
| `git diff --cached` | Shows staged changes compared with the latest commit. |
| `git diff --staged` | An alternative to `git diff --cached`. |
| `git diff <commit1> <commit2>` | Compares two commits. |
| `git diff <commit_hash> -- <file>` | Compares a file against a specified commit. |

Example:

```bash
git diff
```

Compare two commits:

```bash
git diff abc123 def456
```

Compare a particular file:

```bash
git diff abc123 -- index.html
```

## Undoing and Recovering Changes

Git provides several ways to undo changes. Choose the command carefully because some operations can permanently discard local work.

### Unstage a File

```bash
git restore --staged filename
```

Alternatively:

```bash
git reset filename
```

### Discard Unstaged Changes in a File

```bash
git restore filename
```

### Reset to the Previous Commit

Keep changes staged:

```bash
git reset --soft HEAD~1
```

Keep changes in the working directory but unstage them:

```bash
git reset --mixed HEAD~1
```

Discard changes and reset the working directory:

```bash
git reset --hard HEAD~1
```

### Reset to a Specific Commit

```bash
git reset --hard <commit_hash>
```

**Warning:** `git reset --hard` can permanently discard uncommitted changes.

### Revert a Commit

```bash
git revert <commit_hash>
```

Unlike resetting history, `git revert` creates a new commit that reverses the changes introduced by an earlier commit.

### Remove a Tracked File

```bash
git rm filename
```

### Rename or Move a File

```bash
git mv old-filename new-filename
```

### Remove Untracked Files and Directories

```bash
git clean -fd
```

**Warning:** This command deletes untracked files and directories. Review what will be removed before running it:

```bash
git clean -fdn
```

### Abort a Cherry-Pick

```bash
git cherry-pick --abort
```

## Stashing Changes

Stashing temporarily stores working-directory changes so you can switch tasks without creating a commit.

### Save Current Changes

```bash
git stash
```

### Save Changes with a Description

```bash
git stash push -m "Work in progress"
```

### List Stashes

```bash
git stash list
```

### Restore the Most Recent Stash

```bash
git stash apply
```

### Restore and Remove the Most Recent Stash

```bash
git stash pop
```

### Remove a Specific Stash

```bash
git stash drop stash@{0}
```

git tag -a v1.0.0 -m "Version 1.0.0"

### Delete a Local Tag

git push origin --tags

## Advanced Git Commands

### Cherry-Pick a Commit

Apply the changes introduced by a specific commit to the current branch:

```bash
git cherry-pick <commit_hash>
```

### Find a Bug Using Binary Search

Start a bisect session:

```bash
git bisect start
```

Mark the current revision as bad:

```bash
git bisect bad
```

Mark a known working revision as good:

```bash
git bisect good <commit_hash>
```

When Git identifies the problematic commit, end the session:

```bash
git bisect reset
```

### Manage Submodules

Add a submodule:

```bash
git submodule add <repository_url> <path>
```

Initialize and update submodules:

```bash
git submodule update --init
```

Update nested submodules recursively:

```bash
git submodule update --init --recursive
```

### Manage Multiple Working Directories

Create a worktree:

```bash
git worktree add <path> <branch>
```

List worktrees:

```bash
git worktree list
```

Remove a worktree:

```bash
git worktree remove <path>
```

### Inspect Tracked Files

```bash
git ls-files
```

### Optimize the Repository

Check repository integrity:

```bash
git fsck
```

Run Git garbage collection:

```bash
git gc
```

### Create an Archive

Create a ZIP archive from a branch:

```bash
git archive --format=zip --output=archive.zip main
```

Create a TAR archive:

```bash
git archive --format=tar --output=archive.tar main
```

### Configure the Default Text Editor

```bash
git config --global core.editor "editor_name"
```

### Temporarily Ignore Changes to a Tracked File

```bash
git update-index --assume-unchanged filename
```

Stop assuming that the file is unchanged:

```bash
git update-index --no-assume-unchanged filename
```

These commands are local index optimizations, not a replacement for `.gitignore`.

### Rebase While Pulling

```bash
git pull --rebase origin main
```

### Interactive Rebase

```bash
git rebase -i HEAD~3
```

This opens an interactive interface for editing, reordering, combining, or removing recent commits.

### Abort a Rebase

```bash
git rebase --abort
```

## GitHub Repository Workflows

### Create a New Repository Using the Command Line

Create or open your project directory:

```bash
cd /path/to/your/folder
```

Initialize Git:

```bash
git init
```

Create a README file if needed:

```bash
echo "# repository-name" > README.md
```

Stage project files:

```bash
git add .
```

Create the first commit:

```bash
git commit -m "Initial commit"
```

Set the default branch:

```bash
git branch -M main
```

Connect your GitHub repository:

```bash
git remote add origin https://github.com/username/repository-name.git
```

Push the project:

```bash
git push -u origin main
```

### Push an Existing Local Repository to GitHub

If your local project is already initialized with Git:

```bash
git status
git add .
git commit -m "Add existing project files"
```

Connect the remote repository:

```bash
git remote add origin https://github.com/username/repository-name.git
```

Push the current branch:

```bash
git push -u origin main
```

If the remote repository already contains commits that are not present locally, synchronize the histories before pushing. For example:

```bash
git pull --rebase origin main
git push -u origin main
```

Resolve any conflicts before completing the push.

### Clone and Work on an Existing GitHub Repository

Clone the repository:

```bash
git clone https://github.com/username/repository-name.git
```

Enter the project directory:

```bash
cd repository-name
```

Inspect the current branch and changes:

```bash
git status
```

Make changes, commit them, and push:

```bash
git add .
git commit -m "Update project"
git push
```

# GitHub README Markdown Guide

Markdown is a lightweight markup language used to format documentation. GitHub supports Markdown in README files, issues, pull requests, discussions, and other areas.

The following examples demonstrate commonly used Markdown syntax and document nesting.

## Headings

Use the `#` character to create headings. The number of hash symbols determines the heading level.

```markdown
# Heading Level 1

## Heading Level 2

### Heading Level 3

#### Heading Level 4

##### Heading Level 5

###### Heading Level 6
```

## Text Formatting

### Bold Text

```markdown
**This text is bold.**
```

**This text is bold.**

### Italic Text

```markdown
*This text is italic.*
```

*This text is italic.*

### Bold and Italic Text

```markdown
***This text is bold and italic.***
```

***This text is bold and italic.***

### Strikethrough Text

```markdown
~~This text is crossed out.~~
```

~~This text is crossed out.~~

### Inline Code

```markdown
Use `git status` to check your repository.
```

Use `git status` to check your repository.

## Nested Lists

Nested lists organize information into multiple levels. Indent child items beneath their parent items.

### Unordered Lists

```markdown
- Version Control
  - Git
  - GitHub
  - Repository Management
    - Branch Management
    - Commit Management
    - Remote Synchronization
- Documentation
  - Markdown
  - README Files
```

Rendered example:

- Version Control
  - Git
  - GitHub
  - Repository Management
    - Branch Management
    - Commit Management
    - Remote Synchronization
- Documentation
  - Markdown
  - README Files

### Ordered Lists

```markdown
1. Initialize a repository.
2. Stage your changes.
   1. Add individual files.
   2. Add all project files.
3. Commit your changes.
4. Push the commit to GitHub.
```

Rendered example:

1. Initialize a repository.
2. Stage your changes.
   1. Add individual files.
   2. Add all project files.
3. Commit your changes.
4. Push the commit to GitHub.

### Mixed Nested Lists

```markdown
1. Version Control
   - Git
   - GitHub
2. Repository Operations
   - Create a repository
   - Clone a repository
     - HTTPS
     - SSH
3. Documentation
   - README.md
   - LICENSE
```
